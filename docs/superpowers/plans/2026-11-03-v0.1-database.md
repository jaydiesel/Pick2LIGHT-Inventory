# Pick2LIGHT-Inventory v0.1 "Database" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a complete, self-hosted plain-inventory system (no LED hardware yet): server, PostgreSQL schema, web UI, keyboard-wedge scanning, CSV import/export, PDF labels, auth, backups, Docker Compose install.

**Architecture:** One FastAPI process (`server/pick2light`) with a service layer per domain (`core/*`) that owns all database writes; thin routers in `api/*` call services. Custom fields live in JSONB validated by a runtime field engine. The Vue 3 SPA (`web/`) is built to static files and served by the same process. Docker Compose runs `db` (PostgreSQL 16), `server` and `backup`.

**Tech Stack:** Python 3.12, uv, FastAPI, SQLAlchemy 2 (async, asyncpg), Alembic, Pydantic v2, pydantic-settings, argon2-cffi, itsdangerous, Pillow, segno, pylibdmtx, python-barcode, typer, pytest + pytest-asyncio + httpx; Vue 3, TypeScript, Vite, Pinia, Vue Router, PrimeVue, openapi-typescript, Vitest, @vue/test-utils, Playwright; Docker, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-03-pick2light-inventory-design.md` (sections referenced as §N). v0.1 scope is the first row of §16.

## Global Constraints

- Python 3.12; PostgreSQL 16; Node 22 for building the web app (not needed at runtime).
- REST API under `/api/v1`; OpenAPI docs at `/api/docs`, schema at `/api/openapi.json`.
- All schema changes via Alembic migrations in `server/pick2light/migrations/`; never manual DDL.
- Every table: `id` bigint identity PK, `created_at`, `updated_at` (timestamptz, server defaults). Soft-delete tables additionally `deleted_at` (nullable timestamptz): category, log_entry_type, item, unit, location.
- Users table is named `app_user` (`user` is reserved in PostgreSQL); exactly one row.
- Environment variables use prefix `P2L_`.
- Number field values stored as JSON numbers in the field's `number_unit` base unit (§3.5). SI prefixes p n u/µ m k M G; `m` = milli, `M` = mega, case-sensitive; `4k7` form supported (§4.1).
- SKU default pattern `{prefix}-{seq:4}`; unit-code default `{prefix}{seq:4}`; location codes `LOC-{seq:4}`; allowed SKU chars `[A-Za-z0-9._-]`; collision suffix `-2`, `-3`… (§4.2).
- Scanner detection defaults: ≥ 4 chars, inter-key gap ≤ 30 ms, terminated by Enter (§5.1).
- Defaults: trash retention 30 days; backups nightly `03:00`, keep 14; `auth.mode` preselected `password`; `lights.light_children_default = off`.
- Unit `condition` ∈ `new | tested_good | untested | faulty | for_parts`; `status` ∈ `in_stock | checked_out | consumed | disposed`.
- Movement `reason` ∈ `create | import | check_out | check_in | consume | move | adjust | stocktake | undo`; `source` ∈ `ui | scan | import | api | stocktake`.
- Error response body shape for every non-2xx (except 401): `{"error": <code>, "message": <str>, "fields": {<key>: <msg>}?}` with codes `not_found` (404), `conflict` (409), `validation` (422), `invalid_operation` (400). 401 body: `{"error": "unauthenticated", "message": ...}`.
- License GPL-3.0; no model identifiers in code, commits or docs.
- Out of v0.1 (do not build): lights/controllers, command barcodes, stocktake, server evdev scanner, Niimbot/CUPS, label editor UI, importers other than CSV, API tokens, HTTPS, install scripts other than Docker.

## Review Focus

1. **Category field definitions edited after items exist** (field removed, type changed, made required) — existing items must still load and display; saving an item validates only submitted keys plus missing required keys; stale values of untouched fields are kept. → Task 4 test `test_update_keeps_stale_values_of_untouched_fields`, Task 7 test `test_item_loads_after_field_removed`.
2. **Two tabs checking out the same stock at once** — total must never go below zero; one request fails cleanly. → Task 8 test `test_concurrent_check_out_never_negative`.
3. **Unicode and punctuation in names/SKUs/search** (`Ω`, `µ`, `/`, spaces) — SKUs sanitised, `µ` and `u` both accepted, `10kΩ` and `4k7` searches find the item. → Task 5 test `test_sanitize_unicode_and_slashes`, Task 11 tests `test_search_si_alternates`, `test_search_micro_sign`.
4. **Real-world CSV files** — UTF-8 BOM, `;` delimiter (European Excel), blank rows, trailing whitespace; per-row errors reported without aborting the file. → Task 16 test `test_preview_tolerates_bom_semicolon_blank_rows`.
5. **Deleting or moving things that are in use** — deleting a category with items or children, moving a category so inherited keys collide, moving a location under its own descendant: all refused with 409 and a clear message. → Task 3 test `test_move_category_key_collision_refused`; Task 6 test `test_move_location_into_descendant_refused`; Task 7 test `test_delete_category_with_items_refused`.

### Task 2: Engineering-unit parser and formatter

**Files:**
- Create: `shared/si-vectors.json`, `server/pick2light/core/si.py`, `server/tests/test_si.py`

**Interfaces:**
- Produces:
  - `parse_quantity(text: str, unit: str | None, allow_prefixes: bool = True) -> float` — raises `ValueError(message)` on bad input.
  - `format_quantity(value: float, unit: str | None, decimals: int | None = None, use_prefixes: bool = True) -> str`.
  - `search_tokens(value: float, unit: str | None) -> list[str]`.

Rules: strip whitespace; accept trailing unit symbol equal to `unit` (also `ohm`/`ohms` for `Ω`, `R` for `Ω` as in `4R7`); `u` and `µ` (U+00B5) and `μ` (U+03BC) all mean micro; prefix-as-decimal (`4k7` = 4700, `4R7` = 4.7); comma decimal is **not** accepted (error mentions "use a dot"); with `allow_prefixes=False` only plain numbers parse. Format picks the prefix giving a mantissa in [1, 1000), strips trailing zeros, joins without space (`4.7kΩ`); `decimals` caps fraction digits.

### Task 4: Field validation engine

**Files:**
- Create: `server/pick2light/core/fields.py`, `server/tests/test_fields.py`
- Modify: `server/pick2light/core/categories.py` (add `effective_fields` returning `list[FieldSpec]`)

**Interfaces:**
- Consumes: `si.parse_quantity`, `effective_field_defs`.
- Produces:
  - `@dataclass(frozen=True) FieldSpec`: `key, label, type, scope, required, filterable, show_on_label, options: list[dict], number_unit, number_si_prefixes, min, max, decimals`; `FieldSpec.from_definition(fd)`, `FieldSpec.from_dict(d)` (log type field dicts).
  - `validate_values(specs: list[FieldSpec], raw: dict[str, Any], *, existing: dict[str, Any] | None = None, scope: str | None = None) -> dict[str, Any]` — returns the merged dict to store; raises `ValidationFailed` with one message per bad key.
  - `async effective_fields(db, category_id, scope: str | None = None) -> list[FieldSpec]`.
  - `text_values(specs, values) -> list[str]` — strings for search text (selects → option labels, numbers → `si.search_tokens` when `number_si_prefixes`, else plain number string; booleans skipped).

Rules per type: `text`/`long_text` str (trimmed; empty → treated as absent); `number` int/float or str parsed by `parse_quantity(…, allow_prefixes=spec.number_si_prefixes)`, then min/max check; `select` value must be an option `value`; `multi_select` list of option values, deduplicated preserving order; `boolean` bool only; `date` `YYYY-MM-DD`; `url` must start with `http://` or `https://`; `file` positive int (attachment id). `None` in raw removes the key. Keys in raw not in specs (for the given scope) → error `"unknown field"`. Required check: only for specs whose key is absent from the merged result. Keys in `existing` not in specs are kept untouched.

### Task 20: Scanner listener, scan mode bar, dashboard

**Files:**
- Create: `web/src/composables/useScanner.ts`, `web/src/composables/useScanner.test.ts`, `web/src/stores/scan.ts`, `web/src/components/ScanModeBar.vue`, `web/src/components/LocationPicker.vue`, `web/src/views/Dashboard.vue`, `web/src/stores/scan.test.ts`

**Interfaces:**
- Consumes: `apiFetch`, settings `scanner.*`, `POST /scan`, `GET /scan/unknown`, `GET /stock/low`.
- Produces:
  - `useScanner(opts: {minLength, maxGapMs, prefix, suffix, interceptInputs}, onScan: (code: string) => void)` — attaches a `keydown` listener on `window` (capture phase) on mount, removes on unmount.
  - `useScanStore`: `mode: "find"|"check_in"|"check_out"|"consume"` (resets to `find` after 60 s idle), `quantity`, `recent: ScanResult[]` (last 20), `submit(code, extra?)`, `pendingLocationChoice` (set when `action === "needs_location"`).
  - `ScanModeBar.vue`: four mode buttons + quantity input; shows the current mode with colour; Esc resets to find.
  - Dashboard: search box, recent scans list (code, kind, action, message, link), low-stock card, recent unknown scans with "Create item" (→ `/items/new?barcode=`) and "Attach…" (dialog searching items/units/locations → `POST /barcodes`).
  - After a scan: `found` item/unit/location → navigate to its page (in `find` mode only); other actions → toast with the message; `needs_location` → `LocationPicker` dialog listing `locations` (or the full tree when empty), choosing re-submits with `location_id`; `error` → error toast.

Detection algorithm (the tests pin it): keep a buffer and the timestamp of the last key. On a printable single-char key: if the gap since the previous key > `maxGapMs`, reset the buffer to this char; else append. On `Enter`: if buffer length ≥ `minLength` and every gap in the buffer ≤ `maxGapMs` → it is a scan: `preventDefault()`, strip `prefix`/`suffix` if configured (when a prefix is configured, buffers not starting with it are not scans), call `onScan`, clear. If the scan started while focus was in an `<input>/<textarea>` other than one marked `data-scan-target`, and `interceptInputs` is true, remove the scanned characters from that field (restore its value from before the first scanned key) and dispatch `input`. Inputs marked `data-scan-target` (the global search box) receive no removal; the scan is still routed.
